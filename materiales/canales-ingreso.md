# Canales de ingreso para probar en paralelo

La estrategia combina servicios con una venta de producto y una vía de
audiencia. No se debe contar como ingreso hasta que exista un pago confirmado.

## Prioridad 1: servicios técnicos

### Arreglo de bugs web

- Oferta: diagnóstico y corrección de un error concreto en HTML, CSS o JavaScript.
- Precio de entrada: US$15 para un bug pequeño y concreto.
- Alcance: reproducir, corregir, probar y explicar el cambio.
- Evidencia: perfil de Contra y el repositorio público de CajaClara.

### Personalización de CajaClara

- Precio inicial: US$59.
- Alcance: categorías, moneda, colores y estructura inicial de datos.
- Entrega: archivo adaptado y guía breve.

### Landing para negocio local

- Precio inicial: US$79.
- Alcance: una página responsive, formulario de contacto y publicación.

Meta bruta de ejemplo: seis arreglos de US$15 más dos personalizaciones de
US$59 suman US$208. Es una referencia de ventas, no una promesa.

## Prioridad 2: producto digital

### CajaClara

Publicar la demo y vender la versión completa a US$19. Ko-fi requiere conectar
PayPal o Stripe para cobrar; la cuenta de creador ya está reservada, pero falta
la cuenta de pagos del titular.

### itch.io

Puede alojar descargas digitales y permite elegir el porcentaje de ingresos
compartido con la plataforma. Su documentación indica que se necesita PayPal o
Stripe para pagos directos, o completar una entrevista fiscal y requisitos de
pago para su sistema de payouts. No se debe depender de este canal hasta
verificar el método disponible para el titular.

## Prioridad 3: recompensas técnicas

### Bug bounty

Bugcrowd paga solo vulnerabilidades válidas, dentro del alcance y reportadas
primero. Solo se deben probar programas autorizados; nunca escanear sistemas
ajenos ni reportar problemas inventados.

### User testing

Puede complementar el ingreso, pero requiere aprobación, micrófono y PayPal
verificado. No usar respuestas falsas para calificar.

## Prioridad 4: audiencia y contenido

### Wattpad

`wattpad/` contiene una novela serial original de 12 capítulos planificados y
tres capítulos iniciales. Se publica capítulo por capítulo para construir
lectores; la monetización depende de selección editorial, invitación o venta
posterior de una edición/epílogo. No es ingreso rápido.

## Reglas de operación

1. No pagar por adelantado para “desbloquear” recompensas.
2. No usar contraseñas de Gmail como contraseñas de otras plataformas.
3. No aceptar trabajos de hacking fuera de programas autorizados.
4. Medir contactos, respuestas, demos, horas y dinero neto cada dos semanas.
